# Intake And Research Assignments

## Ask What Changes The Investigation

Infer answers already supplied and ask only what remains consequential. Use
reconnaissance to make ambiguous questions concrete. Useful prompts include:

- **Purpose and audience:** What should the reader understand, decide, or do?
  Is this a history, outcome assessment, contribution account, recovery of prior
  work, or input to a present decision?
- **Scope:** Which topics, projects, former names, people, dates, and adjacent
  work belong in the investigation? What is deliberately outside it?
- **Starting evidence:** Which known artifacts, recollections, disputed claims,
  or missing answers should guide the initial search?
  Include earlier evidence companions or graphs that may serve as Trunk sources.
  Record explicit reuse or exclusion policy and known export lineage for tests.
- **Sources:** Which repositories, document stores, designs, discussions, meeting
  records, or measurements are available? Does contributor scope include comments
  and revisions, or only named authorship?
- **Output and effort:** Where should the brief and companion live, who are they
  for, and what depth or time constraints matter? Preserve explicit structure,
  candidate-table requirements, length, and protected/finalized artifacts.

Use the [default research allowance](research-budgets.md) when the user has not
specified one; it need not become another intake question. Distinguish discovery
limits from time to synthesize, edit and deliver. Do not interpret permission for
a long-running investigation as permission for unbounded recursive expansion.

Do not ask all of these mechanically. Explain a material scope assumption and
proceed where useful; keep genuinely dependent work pending if an answer is needed.
Offer another short checkpoint when discoveries change the question, available
sources, or likely conclusions. Routine searches need no approval ceremony.

## Shape The Search

Write the [research plan](research-plan.md) before searching. Map questions to
project aliases, terminology, people, periods, source surfaces, and work types.
Select concrete query combinations by likely value and uncovered questions; do
not create the full Cartesian product. Include simple queries that can find
records using different language, including generic review or prototype titles.
Record why important branches are covered, postponed, or excluded.

Use the [route mapping](search-routes.md) to distinguish work type, artifact form,
location, retrieval route, and query mode. Resolve tool capabilities with the
applicable environment/source skills. Delegate specific branches and exact work
items, including complementary discovery routes; do not give every researcher
the same default search endpoint and call that source diversity.

Use actual subagents or child agent processes. For substantial search branches,
large result sets or multiple substantial document batches, record the intended
fan-out in the plan: search partitions, reading batches, coordinator and available
capacity. Search assignments can divide work types, periods or complementary
routes; reading assignments divide deduplicated sources or record neighborhoods.
A large corpus around one question still warrants multiple readers. Start reading
useful seeds while discovery continues. Reassess workload after each wave, and
record any sequential fallback and its actual constraint. Do not silently replace
requested delegation with one agent wearing several role labels.

Size each worker's next checkpoint to the material it can actually inspect and
return within its context and tool-output limits. Start with a small representative
batch, check the return, then adjust. A partition may contain many candidates;
it need not be displayed or judged in one response. Keep explicit completed and
remaining source IDs so a continuation resumes the unfinished portion. Truncated
tool output is incomplete inspection, even when a script loaded the whole file.

Reserve effort for seed reads and source-derived expansion before synthesis.
Assign a bounded question or record neighborhood, with the next checkpoint,
instead of spending every researcher's budget on initial searches. Return observed
terms, a reference inventory, organizing records and proposed follow-ups with source
locators, following [the reading procedure](reading-and-expansion.md). The coordinator
deduplicates targets and turns consequential leads into work or explicit bounds.
Keep a reader on a useful nearby follow-up when its assignment permits; distribute
larger branches. All new operations still need saved assignments before execution.

The worklist drives searches and subsequent reads. Each item has an owner,
priority, exact request, and state; execution receipts supply what actually ran.
Add discovered vocabulary and surrounding-record leads to the same plan. Keep
the originating source and locator for each lead, including whether a user
supplied it. Do not replace an unexecuted query with a better-looking search log.

For each source route, establish what the tools expose. A file search may find
titles but omit comments, older revisions, attachments, or diagram text. Track
pagination and result caps. When a route fails, record whether the cause is known;
do not turn an unexplained error into a claim that the source does not exist.

Separate discovery from reading. A broad discovery wave creates a candidate
inventory; reading waves answer specific questions and follow new leads. Adjust
partitions if several researchers keep finding the same material.

## Researcher Assignment

Adapt this packet to the task; omit irrelevant fields rather than demanding a form:

> **Question:** The uncertainty this assignment should resolve, stated neutrally.
> **Scope:** Projects, people, dates, aliases, source classes, and exclusions.
> **Starting points:** Known artifacts and prior coverage, with stable IDs/links.
> **Capabilities:** Available tools and confirmed read/access limitations.
> Include the verified read formats and provider guidance, not just tool names.
> **Effort:** Priorities, bounded depth, and when to return unresolved leads.
> Include the shared admission recorder, research stage/branch and ancestry,
> allocation (`baseline`, `followup-N` or `extension`), purpose, remaining
> guaranteed/shared allowance, active-time reporting and checkpoint size.
> Reserve a complete query → triage → selected-read → assessment → lead cycle,
> not just retrievals. Return newly observed high-signal terms and uninspected
> source surfaces promptly so they can run alongside the baseline. Child workers
> share the same caps; they do not each receive a fresh copy of the whole budget.
> **Authority:** Read-only research and the exact permitted output location;
> shared source artifacts and live documents have one designated editing owner;
> independent workers submit graph updates through the validated helper.
> **Return:** Executed queries; candidate sources and read coverage; detailed
> findings with quotations and locators; contradictory and excluded evidence;
> uncertainties; per-source reference scans and dispositions; unlinked vocabulary
> and record leads; completed and proposed follow-ups with their provenance.
> Return a structured list of observed leads with stable local IDs and source
> locators, including terms that navigate the domain without supporting a claim.
> Preserve this original return for reconciliation; do not silently omit it after
> the coordinator writes a summary.
> **Contract and receipts:** Shared task-contract path, unique operation-ID
> prefix, researcher's actor label, evidence-bundle location, and checks that must
> pass before acceptance. Identify any separate capture operator and source reader.
> **Plan:** Assigned work-item IDs and saved plan snapshot, current inventory,
> and how to return new terms, sources, and follow-up requests to the coordinator.
> **Graph:** Shared bundle root, registered actor and parent, assignment ID,
> expected revisions, lease, question/scope/format/version requirements, and
> the helper commands for querying and returning work. Register actual nested
> children under the delegated lead; do not create a separate graph or budget.
> Worker identities are attestations unless verified by the harness. A lease
> expiring does not prove its provider call stopped; reconcile the original.
> **Time accounting:** Name the supervising coordinator/lead who opens this
> actor's activity interval before dispatch and closes it after observed completion.
> The reader keeps that interval open through interpretation and return preparation;
> it does not independently close the clock or replace it with script timings.
> **Reference coverage:** Accessible content surfaces, extraction method, captured
> link/embedded-reference list, inaccessible surfaces and any lossy export limits.
> **Continuation:** Which nearby follow-ups the reader may execute after coordinator
> reconciliation, and when to return a larger branch for a new assignment.

Separate the user's hypothesis from established evidence in the packet. Ask what
would change or weaken an emerging conclusion. Avoid giving every researcher a
desired verdict or asking them to validate another agent's summary as a source.

Researchers may return unexpected relevant findings outside the initial schema.
They should identify their actual read extent and tool limitations, and never
report a linked document as read merely because another source summarizes it.

## Coordinator Reconciliation

Merge source identities and retain the union of inspected sections, not an
inflated count of independent documents. Preserve researcher attribution in the
evidence record where it helps audit work. Keep interpretation distinct from
primary-source quotations. Directly inspect sources supporting pivotal claims.

Use follow-up assignments for specific gaps, contradictions, new vocabulary, or
changed access. Reuse completed work across waves and update the coverage record.
At each wave boundary, reconcile planned items against receipts and every returned
asset against the inventory. Separate retrieved material from what someone read,
then from what was analyzed and used. Add relevant surrounding records as owned
follow-ups rather than leaving them buried in researcher prose. Explicitly record
why a branch is complete, still pending, bounded by access or effort, or dropped.
Match the original returned lead IDs to the consolidated ledger. Every retained
term/reference needs executed follow-up or a specific reviewed bound; a plausible
summary and a valid ledger cannot excuse a lead dropped before import. Report
spending and the remaining frontier by branch and generation. Protect baseline
breadth and priority first follow-ups before optional deeper investigation.
Use graph ingestion status, coverage, leads and next-work queries for this loop;
the [graph command procedure](graph-workflow.md) includes claim, return and recovery
examples for actual nested workers.
Every returned lead is registered before triage; assign it or record its scoped
bound rather than copying only selected leads into another list. Reconcile all
questions attached to a lead, not just the first. Reuse matching work while
preserving every origin; a new path does not reset its budget generation.
Before accepting a return, run the record checks and spot-check its extracted
IDs/claims against retained output. A researcher summary is not a retrieval log.
For large metadata batches, check that each claimed judgment has an inspected
metadata basis and that undisplayed or unfinished rows remain pending. Scripts
may sort, deduplicate or suggest priorities; their default labels are not a
reader's assessment. Repeated wording can be valid for sources sharing the same
basis, so evaluate the evidence rather than requiring unique phrasing per row.
Reconcile the reference scan against available link metadata and the common source
inventory. Review missed organizing labels, unlinked references and exclusion
reasons against actual passages. In a large delegated investigation, assign a
different reader or review subagent a bounded coverage check of pivotal sources
and proposed stopping decisions. It may add leads and reopen research. Rotate an
existing reader when capacity is limited; document any unavailable independent
check. Reviewing a polished summary alone does not satisfy this assignment.
Reconcile actor labels and claimed readers with the assignment; do not attribute
all reads to the coordinator merely because it owns the shared records.
Retain actual child-agent/process identities, assignment scope and returned work
as delegation evidence. For an end-to-end evaluation of this workflow, verify the
requested search, reading and follow-up delegation actually occurred; report a
sequential substitute as partial workflow coverage.
Before stopping, classify gaps by their effect on the reader's central question.
For a consequential missing decision, inspect earlier aliases, review artifacts,
and cross-links before concluding that only later accounts are available.
Record any user-provided source leads separately from independent discovery.
On a research stop, collect existing returns, preserve incomplete work and finish
the main author's synthesis and document refinement under their separate allowance.
If delegation is unavailable, perform the same bounded investigation sequentially
and describe that accurately; do not imply a team was used.
